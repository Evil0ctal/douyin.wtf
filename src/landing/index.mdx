## What it is

**Douyin_TikTok_Download_API** is an open-source, self-hosted data API for
[Douyin](https://www.douyin.com) (抖音), [TikTok](https://www.tiktok.com) and
[Bilibili](https://www.bilibili.com) (哔哩哔哩). You run it on your own machine with
one `docker compose up`. There is no hosted tier, no signup and no quota, and
nothing is proxied through anybody else's server.

It fetches posts, authors and comments, sounds, hashtags, live rooms, trending
boards and search results, and it downloads video and image albums **without a
watermark** — it selects the clean stream the platform already publishes rather
than stripping anything, the clip behind a Douyin live photo included. What it
collects is archived in your own PostgreSQL, so a post deleted upstream is still
readable locally.

A video it has downloaded can be turned into text on the same machine. The
optional transcriber runs FunASR models in a container with no route out, so the
audio never leaves the host and no speech API is called.

It handles the awkward parts rather than leaving them to you: Douyin's
`a_bogus` and `X-Bogus` request signatures, TikTok's and Bilibili's WBI are
implemented natively in Python, short links are expanded and checked against an
allowlist before anything is fetched, and a post id is validated against the
platform's own encoding so an id that cannot exist never costs an upstream
request.

## Try it without installing anything

<CardGrid>
  <Card title="In the browser" icon="laptop">
    <Steps>

    1. Open [demo.douyin.wtf](https://demo.douyin.wtf). The login page arrives
       with the demo account already filled in.
    2. Sign in. You land in the console as a `demo` role.
    3. Go to **Playground**, paste any Douyin, TikTok or Bilibili link, and press
       Parse.

    </Steps>
  </Card>
  <Card title="From a terminal" icon="seti:shell">
    Nothing to register for: the instance publishes its own demo password at
    `/api/v1/auth/demo`. The session is a cookie, not a bearer token.

    ```bash
    PASS=$(curl -s https://demo.douyin.wtf/api/v1/auth/demo | jq -r .data.password)

    curl -s -c jar -o /dev/null \
      -X POST https://demo.douyin.wtf/api/v1/auth/login \
      -H 'content-type: application/json' \
      -d "{\"username\":\"demo\",\"password\":\"$PASS\"}"

    curl -s -b jar -X POST 'https://demo.douyin.wtf/api/v1/parse?wait=25' \
      -H 'content-type: application/json' \
      -d '{"url":"https://www.douyin.com/video/7675505205047348543"}' \
    | jq '.data | {platform, kind, description}'
    ```
  </Card>
</CardGrid>

`?wait=25` is what makes the call synchronous: it holds the connection until the
task finishes and answers `200` with the result. Leave it off and you get `202`
with a task id instead, which is the normal asynchronous path. The ceiling on
this instance is 30 seconds.

The reference is open without a login too —
[`/swagger`](https://demo.douyin.wtf/swagger),
[`/redoc`](https://demo.douyin.wtf/redoc) and
[`/openapi.json`](https://demo.douyin.wtf/openapi.json), in both languages.

<Aside type="caution" title="What the demo is and is not">
It is one small server, shared by everyone, so it is rate-limited to **30
requests per 10 seconds**; going over puts you in a **10-second cooldown** where
every request is refused. That is the demo's limit, not the software's.

The `demo` role reads. It cannot manage identities, edit settings, create keys
or start downloads, and `explain` and `identity` in the Playground are
operator-only because both hand back a live credential. Anything you do there is
visible to whoever looks next — treat it as a public sandbox, and do not paste a
cookie into it.
</Aside>

## Run your own

<Tabs>
  <TabItem label="Docker" icon="seti:docker">
    ```bash
    git clone https://github.com/Evil0ctal/Douyin_TikTok_Download_API.git
    cd Douyin_TikTok_Download_API
    cp .env.example .env          # then set DTK_SECRET_KEY
    COMPOSE_ENV_FILES=.env docker compose -p dtk -f docker/compose.yml up -d
    ```

    Open `http://localhost:8000` and finish the setup in the browser.
    The long version is in the [quick start](/quickstart/).
  </TabItem>
  <TabItem label="Guided installer" icon="seti:powershell">
    A bash script that works out your distribution, offers the right way to
    install Docker, scales the container limits to the machine, generates
    secrets and brings the stack up. Run it again afterwards and it becomes the
    operations menu: status, upgrade, passwords, backups, settings, disk.

    ```bash
    bash <(curl -fsSL https://raw.githubusercontent.com/Evil0ctal/Douyin_TikTok_Download_API/main/install/install.sh)
    ```

    There is a Chinese edition at `install/install.zh.sh`. Both are documented
    in [installation and deployment](/installation/).
  </TabItem>
</Tabs>
